# Echo-Air

A 4-bit build of Gradium's [phonon-31m-en](https://huggingface.co/gradium/phonon-31m-en) English text-to-speech model.
It is a drop-in replacement for Gradium's own `model.q4k.gguf`: the same 55,075,168 bytes, the same file name, and
it loads in Gradium's unmodified `ptts` runtime on CPU. In a pre-registered test on 2,576 synthesized clips, its
speech was **as intelligible as the BF16 model's** (word error rate within 0.5 points) and **closer to BF16's audio
than Gradium's Q4_K file**. It also scored higher predicted quality than that file.

## Highlights

* **As intelligible as BF16.** Word error rate 1.91% vs BF16's 1.83%, a difference of +0.08 points (95% CI −0.02 to
  +0.18), inside the pre-registered +0.5-point margin. No suite is significantly worse. Gradium's Q4_K is
  significantly worse than BF16 on the same test: +0.19 points (+0.06 to +0.32).
* **Closer to BF16's voice than Gradium's Q4_K.** Speaker similarity to BF16's clip of the same sentence is 0.9866 vs
  0.9859, +0.0007 (95% CI +0.0002 to +0.0011), and higher on both suites.
* **Higher predicted quality than Gradium's Q4_K.** UTMOS 4.314 vs 4.281, +0.033 (95% CI +0.027 to +0.039).
* **Same size, same runtime.** A byte-for-byte drop-in for `model.q4k.gguf` in Gradium's repository; nothing else
  changes.

It is **not identical to BF16**: its audio is still slightly further from BF16's than BF16 resampled with a second
seed, and its UTMOS is 0.019 lower than BF16's. See [Limitations](#limitations).

## Results

Every audio result comes from one test, run once: each file synthesized the same 2,576 clips (1,273 distinct
sentences in 2 voices) with stock ptts 0.6.0 on CPU, temperature 0.3, and the same seed per clip for every file.
Verdicts pair sentences (each sentence's 2 voices are averaged first) and use a bootstrap 95% interval. "BF16" is
Gradium's `model.safetensors`; "Gradium Q8_0" and "Gradium Q4_K" are the two GGUF files in Gradium's repository;
"llama.cpp Q4_K" is a second same-size file, the same matrices quantized to Q4_K with llama.cpp's standard quantizer;
the two "BF16" control rows rerun BF16 with the same seeds (runtime noise) and with a second seed (how much BF16
differs from itself when resampled).

### Pre-registered test

Echo-Air passes all four rules, which were written down before the test ran.

|---|---|---|---|
| Primary: Echo-Air vs BF16, word error rate | upper end of the 95% interval below +0.005, and no suite significantly worse | 0.0183 → 0.0191, +0.0008 (−0.0002 to +0.0018) | yes |
| Primary: Echo-Air vs Gradium Q4_K, similarity to BF16 | lower end of the 95% interval above 0 | 0.9859 → 0.9866, +0.0007 (+0.0002 to +0.0011) | yes |
| Guardrail: Echo-Air vs Gradium Q4_K, word error rate | not significantly worse | 0.0202 → 0.0191, −0.0011 (−0.0024 to +0.0002) | yes |
| Guardrail: Echo-Air vs Gradium Q4_K, UTMOS | lower end of the 95% interval above −0.05 | 4.2814 → 4.3141, +0.0327 (+0.0267 to +0.0388) | yes |

These four results are confirmatory. Everything else on this page (per-suite rows outside the rules, the control

Echo-Air's predictions are 20% closer to BF16's than Gradium's Q4_K's at the identical file size.

|---|---:|---|---|---:|---:|
| Gradium Q4_K (baseline) | 0.01608 | baseline | | 0.224 | 23 / 400 |

This screen does not synthesize audio. Each file's model predicts every next audio latent from BF16's own previous

## Quick start

```bash
pip install ptts==0.6.0
hf download webAI-Official/Echo-Air --local-dir Echo-Air && cd Echo-Air
ptts -m . -l en -q q4k -d cpu -v Easton "Echo-Air read this sentence on a laptop CPU at 6:20 PM on November 8th, 2026." -o speech.wav
```

In Python:

```python
import ptts

tts = ptts.TTS(".", lang="en", quant="q4k", device="cpu")
tts.save("speech.wav", "Hello from Echo-Air.", voice="Easton")
```

* The `ptts` command was run from inside this folder with ptts 0.6.0; `quant="q4k"` selects `model.q4k.gguf`, and
  `device="cpu"` is the backend this file was tested on.
* The evaluation used temperature 0.3 (the model's default) and a fixed seed per sentence; pass `seed=` (Python) or
  `-s` (command line) for reproducible audio.
* Voices other than the default come from Gradium's voice catalog and are downloaded on first use; every voice in
  [gradium/phonon-voices](https://huggingface.co/gradium/phonon-voices) works by name or ID.
* Streaming (`tts.stream(...)`) and the other runtimes in [Gradium's guide](https://huggingface.co/gradium/phonon-31m-en)
  work as with Gradium's files; only the CPU backend was tested with this file.

## Limitations

* **Not identical to BF16.** Its audio is less similar to BF16's (0.9866) than BF16 resampled with a second seed
  (0.9872), a significant difference of −0.0007, and its UTMOS is 0.019 lower than BF16's (significant). If the
  closest possible match to BF16 matters more than size, Gradium's Q8_0 (64.5 MB) is closer to BF16 on every measure
  here.
* **Small effects.** The similarity gain over Gradium's Q4_K is +0.0007 on a 0–1 scale; it is significant over 1,273
  sentences but small. The word-error-rate improvement over Gradium's Q4_K (−0.11 points) is not significant.
* **One run.** Each file was measured once on one test set, with one seed per clip; only BF16 was also resampled.
  The screen was also run once.
* **Scope.** English only, two voices (Easton and Master Aldric), sentences of up to about 10 seconds of audio. Long-form
  reading, other voices, voice cloning and listening tests were not evaluated. Measures are automatic (speech
  recognition, speaker embeddings, predicted quality), not human ratings.
* **CPU only.** Results hold for ptts's CPU backend. ptts's other backends (Core ML, CUDA, Metal, Vulkan and the
  browser build) were not tested with this file.
* **Speed was not measured** under controlled conditions. The file has the same size and tensor types as Gradium's
  Q4_K. One example on an Apple silicon Mac: the quick-start command produced 6.3 s of audio in 1.8 s, model loading
  included.
* **Which file.** Results hold for the included `model.q4k.gguf` (sha256 above), byte-identical to the file that was
  evaluated.

## Evaluation protocol

* **Synthesis:** stock ptts 0.6.0 (Linux wheel), CPU backend, 128 single-thread processes on an AMD EPYC 9355 machine
  (container limited to 13.6 CPUs);
  temperature 0.3; one seed per clip, derived from the clip's id and shared by every file; the "second seed" control
  uses a different seed per clip. Voice catalog `gradium/phonon-voices` at revision `0ee17205`. BF16 ran from
  `model.safetensors` in f32, Gradium Q8_0 as `q8_0`, and the three Q4_K files as `q4k`. Every file rendered all 2,576
  clips on CPU. Clips with unusually long audio (≥ 29.5 s, or > 1.5 s per word) numbered 0–4 per file.
* **Sentences:** the 1,088 English target sentences of the Seed-TTS evaluation set (Hugging Face mirror
  `zhaochenyang20/seed-tts-eval` at revision `8f5e1aa2`; 1,073 distinct) and 200 templated sentences full of numbers,
  dates, money, codes and units (the "hard" suite), each in the voices Easton and Master Aldric: 2,576 clips, 1,273
  distinct sentences.
* **Word error rate:** Whisper large-v3 (fp16, greedy, English), Whisper's English text normaliser on both reference
  and transcript, then digit groups split at "." or ":" and "a m"/"p m" joined (so "3:51 p.m." and "3 51 pm" match);
  word errors counted with jiwer, each clip capped at 1, then averaged over a sentence's 2 voices. Not comparable with
  Gradium's published LLM-assisted word error rates.
* **Speaker similarity:** cosine between `microsoft/wavlm-base-plus-sv` speaker-verification embeddings of a file's clip
  and BF16's clip of the same sentence, voice and seed, at 16 kHz.
* **Predicted quality:** UTMOS (`utmos22_strong` from `tarepan/SpeechMOS` v1.2.0), at 16 kHz.
* **Statistics:** every comparison pairs the same sentences (n = 1,273; 1,073 Seed-TTS and 200 hard); 95% intervals
  from 2,000 bootstrap resamples of the per-sentence differences. "No significant change" means the interval includes
  zero.
* **Pre-registration:** the question, primary measures, margins (+0.005 word error rate against BF16; UTMOS within
  0.05 of Gradium's Q4_K) and pass rules were written down before the test ran.
* **Screen:** teacher-forced, 160 WikiText-2 test sentences and 40 hand-written sentences of numbers and dates in the
  voices Hadley and Zoey (400 items); BF16 reference latents from transformers in f32 on CPU, temperature 0.3, one flow
  step; latent error = mean squared difference of the predicted normalised latents; stop frame = first frame whose
  end-of-speech logit exceeds 4.0.

## Responsible Use

Do not use Echo Air to impersonate a real person, to deceive listeners about who is speaking, or to clone a voice without the speaker’s consent. Tell listeners when speech is synthetic where that matters to them.
