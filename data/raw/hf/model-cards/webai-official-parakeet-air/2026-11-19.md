# Parakeet-Air

A 4-bit build of NVIDIA's [Parakeet TDT 0.6B v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) speech
recognition model for 25 European languages, in GGUF for [transcribe.cpp](https://github.com/handy-computer/transcribe.cpp).
It has the same size (485,425,504 bytes) and the same tensor types as handy-computer's widely used
`parakeet-tdt-0.6b-v3-Q4_K_M.gguf`, and it loads in unmodified transcribe.cpp. In a pre-registered test on 22,766
utterances (FLEURS in 25 languages plus LibriSpeech), its word error rate was **within 0.5 points of full precision
(+0.21 points)** where handy-computer's Q4_K_M file is +0.47, and its transcripts were **26% closer to full
precision's** than that file's.

## Highlights

* **Within half a point of full precision.** Pooled word error rate 11.80% vs F32's 11.59%, +0.21 points (95% CI
  +0.16 to +0.26), inside the pre-registered 0.5-point margin.
* **Lower word error than handy-computer's Q4_K_M.** −0.26 points (95% CI −0.32 to −0.20) overall, about 55% of that
  file's increase over F32 removed. It is significantly lower in 8 test sets (Czech, Danish, Croatian, Lithuanian,
  Latvian, Maltese, Dutch, Romanian) and significantly higher in none.
* **Closer to full precision's transcripts.** 3.54 words per 100 differ from F32's transcript, against 4.81 for
  handy-computer's Q4_K_M: −26% (word edits per sentence −0.70, 95% CI −0.74 to −0.66), lower in all 26 test sets.
* **Same size, same runtime.** Same bytes and tensor types as handy-computer's Q4_K_M; it loads in stock
  transcribe.cpp with no code changes.

It is **not identical to full precision**: its word error rate is still significantly higher than F32's overall and
in 10 of the 26 test sets, and handy-computer's 740 MB Q8_0 shows no measurable loss. See [Limitations](#limitations).

## Results

Every result comes from one test, run once per file: each file transcribed the same 22,766 utterances (FLEURS test in
25 languages, 20,146 utterances, plus LibriSpeech test-clean, 2,620) with stock transcribe.cpp on the same GPU.
Verdicts pair the same utterances and use a 95% bootstrap interval that resamples groups of related utterances
(FLEURS by sentence, since several speakers read each sentence; LibriSpeech by speaker and chapter), 8,586 groups in
all. "F32" is handy-computer's full-precision conversion of NVIDIA's weights; "handy-computer Q8_0" and
"handy-computer Q4_K_M" are files from the same repository; "transcribe.cpp quantizer, Q4_K_M" is a second same-size
file, made from the same F32 file with transcribe.cpp's standard quantizer. A second F32 run gave identical
transcripts, so runtime noise is zero.

### Pre-registered test

Parakeet-Air passes all four rules, which were written down before the test ran.

| Check | Rule | Result (95% CI) | Pass |
|---|---|---|---|
| Harness: F32 and handy-computer Q4_K_M on LibriSpeech test-clean | within 0.10 points of handy-computer's published 1.95% and 1.98% | 1.96% and 1.98% | yes |
| Primary: Parakeet-Air vs F32, word error rate | upper end of the 95% interval below +0.5 points | 11.59% → 11.80%, +0.21 (+0.16 to +0.26) | yes |
| Primary: Parakeet-Air vs handy-computer Q4_K_M, word edits from F32's transcript per sentence | upper end of the 95% interval below 0 | 2.65 → 1.95, −0.70 (−0.74 to −0.66) | yes |
| Guardrail: Parakeet-Air vs handy-computer Q4_K_M, word error rate | not significantly worse | 12.06% → 11.80%, −0.26 (−0.32 to −0.20) | yes |

These four results are confirmatory. Everything else on this page (per-language rows and the other files) is
supporting detail and should be read as preliminary.

Parakeet-Air's transcripts are 26% closer to F32's than handy-computer's Q4_K_M's, at the identical file size.

This counts word edits (substitutions, insertions, deletions) between each file's normalized transcript and F32's

## Quick start

```bash
git clone https://github.com/handy-computer/transcribe.cpp && cd transcribe.cpp
git checkout 5700f127
cmake -B build && cmake --build build -j
hf download webAI-Official/Parakeet-Air Parakeet-Air-Q4_K_M.gguf --local-dir .
ffmpeg -i input.mp3 -ar 16000 -ac 1 input.wav
build/bin/transcribe-cli -m Parakeet-Air-Q4_K_M.gguf input.wav
```

* transcribe.cpp expects 16 kHz mono audio; the `ffmpeg` line converts other formats.
* The default build uses Metal on Apple silicon and the CPU elsewhere. For NVIDIA GPUs, the backend this file was
  evaluated on, configure with `cmake -B build -DTRANSCRIBE_CUDA=ON` and run with `--backend cuda`.
* The evaluation used greedy decoding with timestamps and inverse text normalization off. The command line prints
  word and token timestamps by default; those were not evaluated.

## Limitations

* **Not identical to full precision.** Its word error rate is +0.21 points above F32's overall (significant) and
  significantly higher in 10 of the 26 test sets. If accuracy matters more than size, handy-computer's Q8_0 (740 MB)
  showed no measurable loss on this test.
* **Moderate gains.** The improvement over handy-computer's Q4_K_M is −0.26 points of word error rate overall; in 18
  of 26 test sets the difference was not significant.
* **One run.** Each file was measured once on one test set. Greedy decoding on this backend is deterministic (a
  second F32 run gave identical transcripts), so the intervals reflect the choice of utterances, not runtime noise.
* **Scope.** Read speech only: FLEURS (read Wikipedia sentences) and LibriSpeech test-clean (read audiobooks), one
  sentence or short passage per clip. Conversational, noisy, accented, long-form and streaming audio were not evaluated, nor
  were timestamps or inverse text normalization.
* **Backends.** Results hold for transcribe.cpp's CUDA backend. Metal on Apple silicon was smoke-tested only; CPU,
  Vulkan and HIP were not tested with this file.
* **Speed was not measured** under controlled conditions.One example on an Apple silicon Mac with the Metal
  backend: a 4.5 s clip transcribed in 218 ms of processing, 4.3 s in total including model loading.
* **Which file.** Results hold for the included `Parakeet-Air-Q4_K_M.gguf` (sha256 above), byte-identical to the
  file that was evaluated.

## Evaluation protocol

* **Runtime:** stock transcribe.cpp at commit `5700f127`, CUDA backend, one NVIDIA H200 (shared with another job),
  batch transcription through transcribe.cpp's own `scripts/wer/run.py` with `--backend cuda --timestamps none`;
  greedy decoding; inverse text normalization off (the default for this model). The harness passes each test set's
  language code, which transcribe.cpp's Parakeet implementation does not use: the model detects the language itself.
* **Files:** F32, Q8_0 and Q4_K_M from `handy-computer/parakeet-tdt-0.6b-v3-gguf` (sha256 `bbd36acd8c6fbb81…`,
  `5859f77944efcd8e…`, `b68557be1e3c4020…`), which handy-computer converted from NVIDIA's revision `6d590f7`.
* **Test data:** FLEURS test split from `google/fleurs` (revision `70bb2e84`), 25 languages, 20,146 utterances, with
  FLEURS's normalized transcriptions as references; LibriSpeech test-clean, 2,620 utterances, from transcribe.cpp's
  WER manifest. Spanish and Portuguese use the FLEURS configurations `es_419` and `pt_br`.
* **Word error rate:** Whisper's English text normalizer for English (FLEURS English and LibriSpeech) and Whisper's
  basic normalizer for the other languages, applied to reference and transcript; word errors counted with jiwer;
  pooled over words. Utterances whose reference is empty after normalization are skipped (none in this test).
* **Closeness to F32:** word edits between each file's normalized transcript and F32's normalized transcript of the
  same utterance.
* **Statistics:** paired comparisons over the same 22,766 utterances, with a 95% interval from 2,000 bootstrap
  resamples of 8,586 groups (8,499 FLEURS sentences, each read by one or more speakers in one language, and 87
  LibriSpeech speaker-chapters); differences in errors per group are divided by mean words per group to give
  word-error-rate points. "No clear change" means the interval includes zero.
* **Pre-registration:** the question, primary measures, the 0.5-point margin against F32, the harness check and the
  pass rules were written down before the test ran.
* **Comparability:** NVIDIA's and handy-computer's published word error rates use their own normalization and data
  versions. The harness check above reproduces handy-computer's LibriSpeech test-clean numbers within 0.01 points; other
  published numbers are not directly comparable with this page.
